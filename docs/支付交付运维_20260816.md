# SB Index 支付交付运维

## 生产路径

```text
浏览器
  → https://tiance.icu/sbti/api/orders
  → sb-index-report @ 104.207.92.83:33200
  → Tiance Pay @ pay.104.207.93.25.nip.io
  → zpay-alipay 真实通道
  → 支付宝收银页

支付成功
  → Tiance Pay 验证上游回调
  → GET https://tiance.icu/sbti/api/payment/notify
  → sb-index-report 二次验签、验金额、验商户和订单
  → 标记 paid 并交付完整报告
```

## 服务与数据

- systemd：`sb-index-report.service`
- 应用：`/opt/sb-index-report/report-server.mjs`
- 环境：`/etc/sb-index-report.env`（`640 root:sbindex`）
- 订单：`/var/lib/sb-index-report/orders.json`（`600 sbindex:sbindex`）
- 静态站：`/var/www/sb-index-path`
- Caddy 路由：`/sbti/api/*` 反代到 `127.0.0.1:33200`

订单不收集姓名、手机号或邮箱。服务端保存商户订单号、支付状态、随机报告令牌和用户已生成的报告。

## 常用检查

```bash
ssh tiance-agent-sg 'systemctl is-active sb-index-report'
ssh tiance-agent-sg 'curl -fsS http://127.0.0.1:33200/healthz'
curl -fsS https://tiance.icu/sbti/api/healthz
ssh tiance-agent-sg 'journalctl -u sb-index-report --since "30 minutes ago" --no-pager'
```

Tiance Pay 商户名为“SB Index 完整报告”。该商户的 `demo-alipay` 路由为 `suspended`，`zpay-alipay` 路由为 `active`。

## 安全约束

1. `PAY_KEY` 只存在两台服务器的 root 可控环境文件中。
2. 回调必须同时满足：MD5 签名正确、PID 正确、支付方式正确、商品名正确、金额为 `9.90`、状态为 `TRADE_SUCCESS`、回传令牌与本地订单一致。
3. 报告访问令牌为 24 字节密码安全随机数，不使用可枚举的自增 ID。
4. 生成订单限制为每 IP 每分钟 12 次，请求体和报告体均有大小限制。
5. 未付过期订单的前端会要求重新下单；如果网关后续真实确认付款，仍然交付报告，避免“已收款但不发货”。已付订单可通过原链接打开。

## 网络与超时

- 收款机 UFW 只额外允许应用机 `104.207.92.83` 访问 `443/tcp`。
- Tiance Pay 的上游 HTTP 超时从 5 秒调整为 15 秒，用于容纳跨境线路的正常抖动。
- 创建订单按商户订单号幂等，超时不应通过改变订单号无限重试。

## 发布

```bash
npm run deploy
```

发布脚本会构建前端、更新报告服务、重启 systemd 服务并重载 Caddy。环境文件和订单数据不会被覆盖。
